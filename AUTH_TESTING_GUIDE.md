## What's Happening Behind the Scenes

### On Sign Up:
1. Form data sent to `/api/auth/signup`
2. Supabase Auth creates user account
3. Member record automatically created in `members` table
4. Session returned to frontend
5. Success message shown

### On Sign In:
1. Form data sent to `/api/auth/signin`
2. Supabase Auth verifies email/password
3. Member data fetched from `members` table
4. Session stored in browser localStorage
5. Redirected to dashboard

## API Endpoints Used

### Sign Up
```
POST /api/auth/signup

Sends: {
  email: string,
  password: string,
  fullName: string,
  phone?: string
}

Returns: {
  success: boolean,
  user: { id, email, ... },
  member: { id, full_name, ... },
  session: { access_token, ... }
}
```

### Sign In
```
POST /api/auth/signin

Sends: {
  email: string,
  password: string
}

Returns: {
  success: boolean,
  user: { id, email, ... },
  member: { id, full_name, ... },
  session: { access_token, ... }
}
```

## Troubleshooting

### Issue: "Email already in use"
**Solution**: Use a different email (e.g., testuser2@example.com)

### Issue: Sign up works but can't sign in
**Solution**: 
1. Check the email is correct
2. Password must be exactly as entered during signup
3. Check browser console (F12) for errors

### Issue: Dashboard shows blank after login
**Solution**:
1. Check if member record was created in Supabase
2. Verify the user_id matches in members table
3. Check browser console for errors

### Issue: Member record not created
**Solution**:
1. Ensure members table exists (run SQL migrations)
2. Check Supabase connection (verify env variables)
3. Check browser console for error messages

### Issue: Redirect not working
**Solution**:
1. Clear localStorage: `localStorage.clear()` in console
2. Refresh page
3. Try signing in again
